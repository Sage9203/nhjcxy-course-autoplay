# 南航金城学院课程自动联播（手动开启）
[![FOSSA Status](https://app.fossa.com/api/projects/git%2Bgithub.com%2FSage9203%2Fnhjcxy-course-autoplay.svg?type=shield)](https://app.fossa.com/projects/git%2Bgithub.com%2FSage9203%2Fnhjcxy-course-autoplay?ref=badge_shield)


手动开启后，当前视频自然播放结束时，脚本核对平台现有完成记录，再按课程目录进入下一讲并尝试播放，减少逐节切换的操作。

**适用站点：** `nhjcxy.haiqikeji.com` 的课程学习页。本脚本为非官方工具，目前仅适配该站点；其他学校或其他海旗平台需要另行适配。

**当前版本：1.2.1** · [Greasy Fork 安装与更新](https://greasyfork.org/zh-CN/scripts/602633) · [问题反馈](https://github.com/Sage9203/nhjcxy-course-autoplay/issues)

## 功能

- **手动控制：** 使用页面右下角开关开启或停止，每次完整刷新默认关闭。
- **课节编号核对：** 将网站目录数据、页面目录与当前视频来源对应。即使切课后地址栏编号未更新，也按实际课节判断。
- **完成后再继续：** 当前视频自然结束后，先留出约 3.5 秒缓冲，再只读查询平台记录。核对到该课节已完成后，脚本才继续进入下一讲。
- **有限等待：** 平台记录尚未确认时等待重查；认证失败、记录无法对应或等待超限时停止，并显示提示。
- **避免重复切课：** 平台已经进入相邻下一讲时，脚本等待对应播放器加载，避免重复点击或跳到下下讲。
- **异常与目录边界处理：** 多个播放器、媒体报错、加载或播放超时等情况会停止。目录末尾自动结束；下一项含非视频内容、子项目或不可选时交还手动操作。
- **本地诊断：** 显示播放器状态和上次完成核对结果，支持主动复制或下载日志。

## 安装与使用

1. 安装 Tampermonkey 等兼容的用户脚本管理器，再安装本脚本。
2. 停用旧私用版、`1.2.0-test.1`、`1.2.0-test.2` 或其他同类切课脚本，只保留一份联播脚本启用。
3. **完整刷新课程的实际学习页**，等待目录和视频加载。脚本需要在页面初始化时观察本站目录请求；安装后未刷新，可能无法取得目录。
4. 正常开始播放当前视频，再点击右下角“开启自动联播”。
5. 需要停止时点击“停止自动联播”。停止会取消脚本后续的查询与切课，当前视频不会被暂停；已经交给浏览器的播放动作仍可能完成。

如果开启时视频已经结束，请先手动进入下一讲并播放，再开启联播。脚本不会从已结束的画面推断本次观看完成。

手动选择课程目录、使用浏览器前进后退、换课程、离开学习页或目录查询上下文变化时，联播会停止。通过前进、后退恢复缓存页面后，请完整刷新，再手动开启。

## 完成核对与等待范围

脚本查询的是平台**现有记录是否为已完成**，不直接提交或修改学习进度。对已完成课节正常重看时，查询仍可能确认其现有完成状态；这不表示本次观看一定新增了一条记录。

核对必须同时符合已观察到的课节编号、章节与课节标题及完成字段组合。单独显示 100%、未知学习中状态、重复记录或字段冲突，都不会被当作已完成。

自然结束后先缓冲约 3.5 秒；随后最多查询 6 次，重查间隔至少 5 秒，单次等待最多 8 秒，核对总预算为缓冲后 60 秒。**这些是本地保护上限，不是平台保存延迟的测量结果。** 超出预算、认证或业务失败、响应结构变化时，脚本停止，便于检查学习记录或保存日志。

完成核对控制的是脚本自己的点击及播放请求。网站若自行提前切课，脚本会核对刚刚结束的那一讲，并避免重复点击；它不会主动暂停网站正在播放的视频。

本脚本不调整播放倍速、不拖动播放进度、不补发学习心跳或学习结束记录。

## 后台播放

标签页在后台时，只要浏览器和网站继续允许视频播放，页面脚本仍在运行，联播可以继续。后台定时器可能被延迟，切课等待时间也可能变长；恢复执行时若已超过核对截止时间，脚本会停止。

电脑休眠、标签页被冻结或丢弃、自动播放被阻止、网站暂停视频或网络中断，都会影响连续播放。当前尚未完成多浏览器及长时间后台的完整实测。

## 适配要求

脚本需要在网页初始化时运行，并能观察本站目录请求、访问网站现有的请求客户端。脚本管理器的注入时机或隔离方式可能影响这些能力。

查询沿用网站现有客户端鉴权，遵循网站原有的登录状态和登录过期处理。目前通过网站内部 webpack 模块 `51953` 取得现有请求客户端，并检查客户端形状与 `/api` 基址。该模块编号属于网站内部实现；网站更新后可能需要重新适配。遇到“未捕获目录”时先确认只启用一份脚本，再完整刷新；仍失败可保存日志反馈。

## 日志与隐私

展开“日志与诊断”，选择“复制日志”或“下载日志”。浏览器不允许复制时可使用下载按钮；遇到问题请在刷新前保存日志。

- 最近 150 条事件只保留在当前页面内存中，刷新后清空，没有自动上传日志的功能。
- 日志包含课程编号、课节编号、标题、目录位置、时间、页面可见性、播放器状态、完成判定、查询次数及安全错误分类。
- 网站目录和实际视频地址用于课节关联；完整媒体地址、签名参数和完整平台响应不会写入导出日志。
- 必要的学校、课程和用户查询上下文来自网站自身成功发出的目录请求；学校和用户参数仅留在页面内存，不进入导出日志。
- 脚本不提取或复制登录令牌，也不自行设置认证请求头。网站现有客户端自身仍会按原逻辑访问登录存储及处理令牌更新，不能把整条调用说成完全没有存储访问。
- 不额外下载可执行代码，不申请额外的用户脚本管理器 API 权限。

分享日志前，请检查课程编号和课节标题，按需要遮挡。截图也可能包含网页中的账号资料，请自行检查。

## 测试与反馈

当前 1.2.1 已通过 70 项离线逻辑测试，覆盖目录身份、只读查询、完成判定、有限重试、停止取消、旧响应、换课、平台抢先切课和日志隐私等场景。离线测试不能替代真实浏览器、真实平台及后台长期运行的验证。

1.2.0 发布前，2026-10-29 的用户实测日志记录了一次完整后台流程：视频自然结束后，查询确认该课节已完成，再进入相邻下一讲并开始播放；学习记录页也显示该课节已完成。该次运行未出现核对错误、重复点击或跨讲跳转。连续多讲循环、停止取消和失败路径有离线测试覆盖；这份实测日志没有记录真实手动停止，也不代表多浏览器或长时间运行均已验证。

可在本脚本的 Greasy Fork“反馈”页提交问题。建议附上：

- 浏览器、脚本管理器名称及版本，以及脚本版本。
- 发生问题时是否在后台，面板显示的提示。
- 可复现步骤及检查、遮挡后的本地日志。

1.2.1 对客户端适配检查、完成判定和重复分支做了精简。本版本尚未在真实平台重新验证；此前版本的单次实测不能视为 1.2.1 已完成实测。

## 开发

使用 Node.js 22 或更新版本，无第三方依赖，无须运行 `npm install`。

```sh
npm run build
npm run check
npm test
```

- `src/main.user.js`：用户脚本模板、面板与播放状态机。
- `src/catalog-identity.js`：目录与课节身份核对。
- `src/catalog-context-runtime.js`：观察网站目录请求，维护页面内的查询上下文。
- `src/platform-progress-reader.js`：复用网站现有客户端，只读查询完成记录。
- `src/completion-gate.js`：目标课节完成判定、有限等待与取消。
- `dist/nhjcxy-course-autoplay.user.js`：可安装的完整脚本，与 Greasy Fork 1.2.1 发布内容一致。
- `tests/`：Node.js 内置测试运行器及合成浏览器模型；使用虚构数据，不连接真实账户或平台。

构建脚本将模块嵌入主模板，不下载代码、不压缩或混淆。修改源码后运行构建与测试，再更新 Greasy Fork 上原脚本的版本。优先通过 Greasy Fork 安装，以沿用现有更新渠道。
