# 安全设计与扫描告警评估

评估日期：2026-11-06。适用版本：1.2.1，代码提交 `9646e1d969f99a9c597d1e5c5671e10ca5264a02`。

本文记录当前实现的信任假设和静态审查结果，不表示已完成渗透测试，也不保证所有潜在风险已被排除。新增可复现攻击路径时，应重新评估。

## 信任边界

脚本以 `@grant none` 在目标学校的学习页面运行，依赖该页面已有的 JavaScript、DOM、目录数据和请求客户端。它不提供与恶意页面代码之间的安全隔离，也不具备独立验证平台返回学习记录真实性的能力。

如果页面脚本、网站部署或同页面的其他脚本被攻击者控制，身份映射、请求和显示结果可能受到影响。闭包、字段筛选和错误分类用于减少意外暴露与错误操作，不能视为抵抗已控制页面环境的攻击者的安全边界。

## 告警 1：AI Scan / CWE-829

位置：`src/platform-progress-reader.js` 中的 `require(51953).A`。

实现通过向页面已有 webpack chunk 数组添加空模块表和本地回调，获得模块解析器，再调用固定编号的模块取得网站现有 HTTP 客户端。此步骤不下载额外代码，不根据平台响应构造代码，也不使用 eval；但调用模块仍可能执行其工厂，不能把它说成纯数据读取或保证没有副作用。

当前检查包括 HTTPS 同源、模块工厂存在、客户端可调用且具有 get 方法，以及 baseURL 为 /api。这些是适配检查，不是完整性认证；被替换的客户端仍可能满足这些条件。固定模块编号也可能在网站更新后失效或指向其他功能。

脚本随后请求固定的 /user/get_study_progress 路径，复用网站已有的鉴权行为；脚本不自行提取令牌或设置认证头。网站客户端本身仍可能访问登录存储、刷新令牌或执行拦截器。

审查结论：确认存在对页面运行时的信任依赖与模块调用副作用风险。目前未从该告警中确认新增的跨信任边界攻击路径。建议在维持当前架构时将其记录为已接受的设计风险，不宣称已修复。1.2.1 移除了函数文本哈希绑定；恢复该绑定可以检测某些实现变化，但不能认证整个页面运行时。

## 告警 2：AI Scan / CWE-913

位置：`src/catalog-context-runtime.js` 中对 XMLHttpRequest.prototype.open/send 和 window.fetch 的包装。

所有使用这些入口的请求都会经过包装函数，但只有同源、GET、路径严格为 /api/user/yee_node_select 的目录请求才进入响应观察流程。不匹配的请求交由原函数处理。匹配响应还会检查状态、最终 URL 的查询上下文及数据结构。

目录字段经过筛选，媒体地址单独保留在页面内存；学校和用户查询参数留在查询上下文，不进入导出日志。这里没有向任意接收方上传这些记录的功能。fetch 包装返回原 Promise；dispose 仅在入口仍等于本脚本包装时恢复原函数。

这些措施不等于零风险：共享 API 被修改，仍可能与网站代码或其他包装器相互影响；页面环境也无法保证闭包数据绝不会经由被篡改的内建函数暴露。转发参数、保持返回对象和条件恢复只能降低部分兼容性影响。

审查结论：确认存在共享网络 API 包装的兼容性和完整性风险；当前代码不支持“读取并保存所有流量响应”的概括。暂未确认独立的数据外传途径。建议在维持当前架构时记录为已接受的设计风险，而不是声称没有任何风险。
